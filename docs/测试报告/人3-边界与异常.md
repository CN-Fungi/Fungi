### 3-09 连不上时的取证：运行日志

- **前置**：v0.7.0 的 exe 包（`logs/` 是这一版才有的；旧包里没有，拿不到就写「不可测：缺带日志的新包」）
- **步骤**：① 双击 `Fungi.exe`，先什么都不做，看 exe 同级有没有多出 `logs\` 文件夹与 `fungi-<今天日期>.log`
  → ② 打开那个文件，找到本次运行的横幅 → ③ 把 `config.json` 的 `endpoint` 临时改成连不上的地址（如 `http://127.0.0.1:1/v1`），发一句话
  → ④ 再看日志文件 → ⑤ 托盘菜单点「打开日志」、帮助页最后一节点「打开日志目录」，都应打开同一个文件夹
  → ⑥ 有第二台机器时：让朋友用**错的 token** 加入，看房主那台的日志
- **期望**：文件在 exe 旁边、一天一个（`fungi/runlog.py::logs_dir()`，打包版下 = `config.PROJECT_ROOT` 即 exe 目录）；
  横幅里有 `fungi 0.7.0`、`frozen=True`、`config=<路径> exists=`、`model=… endpoint=… api_key=True`、`ghostworld=…`，
  且**没有 api_key 明文**；第三步之后有一行 `model call to … failed: Connection failed: …`（`llm.py::_fail`）；
  第六步房主日志里有一行 `used the wrong token on /api/…`，且那行**不带 token 本身**；
  同一条失败 60 秒内只写一行（`runlog.warn_once` 的 `THROTTLE_S = 60`）
- **实际**：
- **判定**：待测
- **证据**：日志文件本身（附到 Issue 前先扫一眼有没有自己的私密内容）+ `logs\` 文件夹截图
- **收尾**：把 `endpoint` 改回去
- **注意**：日志里没有 api_key、没有房间 token 是设计（spec §45），不是缺陷
