# Fungi 测试：总说明与记录口径

四位（一个开发者 + 三个测试）共用这一套。**每一份报告由一个人独立填写**，别多人改同一个文件。

| 文件 | 谁填 | 什么时候 |
|---|---|---|
| `人1-本机能力.md` | 人1 | 第一轮 D+2，回归 D+4 |
| `人2-界面与端.md` | 人2 | 同上 |
| `人3-边界与异常.md` | 人3 | 同上 |
| `场1-双机基线.md` | 人1（记录员） | 场① 当晚 |
| `场2-文件与同意.md` | 人2（记录员） | 场② 当晚 |
| `场3-三机与异常.md` | 人3（记录员） | 场③ 当晚 |

测试对象是 **v0.6.1 的 exe 包**（解压后与 `Fungi.exe` 同级有 `README.md` 和 `docs/测试人员必看！.docx`）。只有「自测钩子」和「视频理解」两条要源码方式。

---

## 一、开跑前，每台机器都要做的 10 分钟

1. exe 解压到**纯英文路径**（中文路径下 PyInstaller 有坑），双击 `Fungi.exe`。
2. 设置页填自己的 key：Endpoint `https://api.deepseek.com/chat/completions`、模型 `deepseek-v4-flash-vision-exp`（只有这个能识图）。
3. 手机端页看**防火墙那一行**：显示「未放行」就点它，自己发起 UAC；取消过会留一个按钮手动重试。**这一行必须截图**。
4. 确认解压目录下生成了 `data/` 与 `config.json`。
5. 往群里发一张「环境卡片」：机器名 / 解压路径 / 防火墙那一行截图 / 模型配置成功截图。
6. 每场开跑前**清空 `data/`**（干净状态），跑完把整个 `data/` 复制留档当证据。

> `config.json` 里有你的 API key：**绝不入库、绝不发群里**。

## 二、记录口径（三个人用同一套，否则报告没法汇总）

**判定只有三态**：`通过` / `失败` / `不可测（写清缺什么）`。没有"好像可以"。

**每条用例记六项**：编号 · 前置 · 步骤 · 期望 · 实际 · 证据。

**证据至少给两种**：

- 录屏 ≥10 秒 —— 桌面控制、文件传输、断线重连**必须**录屏；
- 关键截图 —— 界面状态、提示文字、报错；
- 数据目录现场 —— `data/mail/`、`data/comm/`、`data/transfers/`、`inbox/<来源主机>/` 的文件列表与内容片段。

**失败的当场开 Issue**，别回家再写。标题格式：

```
[场1-03] 断线重连后卡片没有重放
```

正文按这个填：

```
环境：Windows 11 / 打包版 v0.6.1 / 同网段 192.168.x.x / 谁是 server 谁是 client
前置：清空 data/ 后新建房间，token = fungi-test
步骤：① … ② … ③ …
期望：…
实际：…
证据：录屏 / 截图 / data 目录截图
复现率：3 次中 3 次
```

## 三、六条「不是 bug」，报之前先对一眼

1. 信使默认**不自动回信**——想回才显式发话，它不理你是设计。
2. 信使被问日记会**保密**，这是设计。
3. 桌面控制**默认关**，要去设置页「实验性」一节打开。
4. 文件的增删改**该走命令**（`del` / `ren` / `move`），它不走 GUI 是对的；而且 `del` **不进回收站**。
5. 文件传输必须**对方同意**才落盘，权限滑块拨到「允许」后就不再弹卡。
6. 关掉信使后留言**直达**会话视图，不是坏了。

## 四、怎么提交

- 先在 `CN-Fungi` 组织里把自己加进来，**用自己的 GitHub 账号**提 PR。
- 只动 `docs/测试报告/` 下属于你的那一份；**不改 `fungi/` 下的代码**、不动 `README.md` 与 `docs/README-详细版.docx`、不动 `pyproject.toml`。
- **一律开分支提 PR，不直接 push main**。发现功能问题一律开 Issue，不自己改。
